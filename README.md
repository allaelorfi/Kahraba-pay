# كهرباء باي — KahrabaPay

مشروع تجريبي لإدارة خدمات الكهرباء، مبني باستخدام **React + Vite** للواجهة الأمامية، و**Node.js + Express** للواجهة البرمجية، مع **PostgreSQL** لتخزين بيانات المستخدمين والحسابات والاستهلاك والشحن والتنبيهات وتذاكر الدعم.

---

## آخر الإضافات

هذه الإضافات الأحدث على المشروع:

- **واجهة مخصصة لحسابات الفاتورة الشهرية في الشاشة الرئيسية**
  سابقًا كانت الشاشة الرئيسية تعرض بطاقة "رصيد الشحن المسبق" لكل الحسابات دون استثناء، حتى لو كان نوع الخدمة "فاتورة شهرية". الآن تتحقق الشاشة الرئيسية من نوع الحساب (`serviceType`):
  - **شحن مسبق** → بطاقة الرصيد المعتادة (المبلغ المتبقي، الاستهلاك اليومي، زر "اشحن الآن").
  - **فاتورة شهرية** → بطاقة مخصصة تعرض المبلغ المستحق وفترة الفاتورة وتاريخ الاستحقاق، مع تنبيه عند اقتراب الموعد، وزر "عرض الفاتورة ودفعها" ينقل المستخدم إلى صفحة الفاتورة الكاملة. كما تتغيّر البطاقتان السريعتان أسفل الشاشة لتعرضا استهلاك الفترة وموعد الاستحقاق بدل بيانات الرصيد.

- **تمييز زر تسجيل الدخول عن زر إنشاء الحساب**
  في شاشة الدخول، أصبح نص زر المتابعة يتغيّر حسب التبويب النشط:
  - عند **تسجيل الدخول** → **"تسجيل"**.
  - عند **حساب جديد** → **"متابعة"**.

## الميزات المطبّقة في هذه النسخة

- شاشة تسجيل الدخول وإنشاء الحساب باستخدام رقم الهاتف وكلمة المرور.
- إمكانية إنشاء مستخدم جديد بالاسم ورقم الهاتف وكلمة المرور.
- حفظ بيانات المستخدمين والحسابات في PostgreSQL.
- فصل بيانات المستخدمين والحسابات بحيث لا تظهر بيانات مستخدم آخر.
- وجود حساب تجريبي مخصص للعرض والاختبار.
- إنشاء حسابات وعدادات مرتبطة بالمستخدم المسجَّل دخوله.
- التحقق من البيانات المدخلة في الواجهة والخادم.
- التحقق من أرقام الهاتف وأرقام العدادات ومنع القيم غير الصحيحة.
- التحقق من الحقول المطلوبة في النماذج الأساسية.
- إرجاع رسائل خطأ عربية وحالات HTTP مناسبة عند وجود بيانات ناقصة أو غير صحيحة.
- استخدام `dotenv` لقراءة بيانات الاتصال بقاعدة البيانات ومفتاح JWT من ملف `.env`.
- عدم وضع كلمة مرور PostgreSQL مباشرة داخل `server.js`.
- تشفير كلمات المرور باستخدام `bcryptjs` وعدم تخزينها كنص صريح.
- استخدام JWT للمصادقة وحماية المسارات التي تحتاج إلى تسجيل الدخول.
- منع المستخدم من الوصول إلى بيانات حسابات مستخدمين آخرين.
- إضافة معالجة أخطاء مركزية في Express.
- إضافة مسار 404 للمسارات غير الموجودة.
- إضافة الوضع النهاري والليلي من خلال إعدادات الحساب، مع حفظ الاختيار في المتصفح.
- استخدام أيقونات Font Awesome بدل الرموز التعبيرية في الواجهة.
- واجهة مخصصة لحسابات الفاتورة الشهرية في الشاشة الرئيسية (انظر "آخر الإضافات" أعلاه).
- توفير صفحات لإدارة الحسابات وربط العدادات والاستهلاك والشحن والدعم والتنبيهات.
- توفير بيانات استهلاك وسجل قراءات للاختبار والعرض.

## تشغيل PostgreSQL من pgAdmin

### 1. تثبيت PostgreSQL

ثبّت PostgreSQL وشغّل خادم PostgreSQL المحلي، ثم افتح **pgAdmin**.

### 2. إنشاء قاعدة البيانات

أنشئ قاعدة بيانات باسم:

```
kahrabapay
```

### 3. إنشاء الجداول

افتح **Query Tool** على قاعدة البيانات `kahrabapay`، ثم نفّذ محتوى:

```
backend/schema.sql
```

يمكن أيضًا استخدام سكربت إعداد قاعدة البيانات الموجود في المشروع، من داخل مجلد `backend`:

```bash
npm run db:setup
```

## إعداد ملف البيئة .env

يوجد ملف نموذجي:

```
backend/.env.example
```

انسخه إلى:

```
backend/.env
```

ثم عدّل بيانات الاتصال بقاعدة البيانات. مثال:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=kahrabapay
DB_USER=postgres
DB_PASSWORD=YOUR_POSTGRES_PASSWORD

PORT=4000

JWT_SECRET=CHANGE_ME_TO_A_LONG_RANDOM_SECRET
```

- استبدل `YOUR_POSTGRES_PASSWORD` بكلمة مرور PostgreSQL الموجودة عندك.
- استبدل `CHANGE_ME_TO_A_LONG_RANDOM_SECRET` بمفتاح JWT عشوائي وطويل.

### حماية ملف .env

- لا يجب رفع ملف `.env` إلى Git أو مشاركته مع الآخرين إذا كان يحتوي على كلمات مرور أو مفاتيح سرية.
- ملف `.env` موجود ضمن `.gitignore`.
- يتم تحميل المتغيرات في الخادم باستخدام:

  ```js
  require("dotenv").config();
  ```

- ويتم استخدام كلمة مرور قاعدة البيانات من خلال:

  ```js
  process.env.DB_PASSWORD
  ```

  بدل كتابة كلمة المرور مباشرة داخل كود الاتصال بقاعدة البيانات.

بعد إنشاء الجداول، يمكن تشغيل بيانات الحساب التجريبي إذا كان سكربت البذرة موجودًا في المشروع.

## قاعدة البيانات

يستخدم المشروع PostgreSQL لتخزين البيانات بدل الاعتماد على بيانات ثابتة داخل الواجهة. من البيانات التي يتم التعامل معها:

- المستخدمون
- الحسابات
- العدادات
- بيانات الاستهلاك
- القراءات
- عمليات الشحن
- الفواتير الشهرية
- التنبيهات
- تذاكر الدعم

تتم عمليات الوصول إلى قاعدة البيانات من خلال `pg`.

---

## المصادقة وحماية البيانات

- يستخدم المشروع JWT للمصادقة.
- بعد تسجيل الدخول يتم استخدام رمز JWT مع الطلبات التي تحتاج إلى مصادقة.
- المسارات المحمية تتحقق من المستخدم المسجَّل دخوله قبل السماح بالوصول إلى البيانات.
- يتم التحقق من ملكية الحساب قبل إرجاع أو تعديل بياناته، حتى لا يستطيع مستخدم الوصول إلى حساب مستخدم آخر.

## كلمات المرور

لا يتم تخزين كلمات المرور كنص صريح. يستخدم المشروع `bcryptjs` لتشفير كلمات المرور والتحقق منها عند تسجيل الدخول.

---

## التحقق من البيانات ومعالجة الأخطاء

تم تطبيق التحقق ومعالجة الأخطاء على النماذج والمسارات الموجودة فعليًا في المشروع، ومنها:

- تسجيل الدخول
- إنشاء حساب جديد
- ربط العداد
- إضافة حساب أو عداد
- الشحن
- فتح تذكرة دعم
- إعدادات التنبيهات

يتم التحقق من البيانات في الواجهة، كما توجد عمليات تحقق إضافية داخل الخادم. عند وجود قيمة ناقصة أو غير صحيحة، يعيد الخادم استجابة HTTP مناسبة ورسالة خطأ واضحة، مثال:

```js
if (!label || !meterNumber) {
  return res.status(400).json({
    error: "اسم العقار ورقم العداد مطلوبان."
  });
}
```

### معالجة أخطاء Express

يحتوي الخادم على معالجة مركزية للأخطاء بالإضافة إلى مسار 404. إذا تم طلب مسار غير موجود، يعيد الخادم استجابة توضح أن المسار غير موجود، كما تتم معالجة الأخطاء غير المتوقعة داخل middleware مخصص للأخطاء.

## اختبار الحقول الفارغة

يمكن اختبار التحقق من الواجهة باتباع الخطوات التالية:

1. **تسجيل الدخول** — افتح شاشة تسجيل الدخول واضغط على زر المتابعة مع ترك الحقول فارغة. يجب أن تظهر رسالة توضح الحقول المطلوبة.
2. **ربط العداد** — افتح صفحة ربط الحساب واترك رقم العداد فارغًا ثم حاول الإرسال. يجب أن تظهر رسالة تحقق مناسبة.
3. **إضافة حساب أو عداد** — افتح نموذج الإضافة وحاول الحفظ دون إدخال البيانات المطلوبة. يجب رفض العملية وإظهار رسالة واضحة.
4. **الدعم** — افتح صفحة الدعم وحاول إرسال تذكرة دون إدخال عنوان المشكلة أو تفاصيلها. يجب رفض الطلب وإظهار رسالة تحقق.
5. **أرقام الهاتف والعداد** — جرّب إدخال حروف أو رموز غير مناسبة في رقم الهاتف أو رقم العداد. توجد عملية تحقق في الواجهة، كما يعيد الخادم التحقق من القيم قبل حفظها.

## صفحة الاستهلاك

تعرض صفحة الاستهلاك البيانات المتاحة للحساب النشط، ومنها:

- استهلاك آخر 7 أيام
- معدل الاستهلاك
- إجمالي الشهر
- نسبة التغيّر عن الشهر السابق
- آخر قراءة للعداد (القراءة السابقة، القراءة الحالية، الاستهلاك بالكيلوواط/ساعة، الفئة والتعريفة)
- سجل القراءات الشهرية

كما تتعامل الواجهة مع حالة عدم وجود بيانات استهلاك أو قراءات سابقة، حتى لا تتسبب البيانات الفارغة في توقف الصفحة.

## الحسابات الجديدة

عند إنشاء مستخدم جديد، يتم حفظ بياناته بشكل مستقل في قاعدة البيانات. الحسابات الجديدة لا تستخدم بيانات مستخدم آخر. إذا لم توجد قراءات أو بيانات استهلاك للحساب الجديد، تعرض الواجهة رسالة مناسبة بدل محاولة استخدام بيانات غير موجودة.

## الشاشة الرئيسية وحسابات الفاتورة الشهرية

تتكيّف الشاشة الرئيسية مع نوع خدمة الحساب النشط:

- **شحن مسبق** → بطاقة الرصيد المعتادة، مع زر "اشحن الآن" وتنبيه عند قرب نفاد الرصيد.
- **فاتورة شهرية** → بطاقة تعرض المبلغ المستحق، فترة الفاتورة، وتاريخ الاستحقاق، مع تنبيه عند اقتراب الموعد، وزر ينقل المستخدم مباشرة إلى صفحة الفاتورة الكاملة لعرضها ودفعها.

## الوضع النهاري والليلي

```
الحساب ← الإعدادات العامة
```

ويتم حفظ اختيار المستخدم في المتصفح حتى يبقى الإعداد بعد إعادة فتح الصفحة.

## ملاحظة حول TaskForm و routes/tasks.js

المشروع الحالي هو تطبيق KahrabaPay، ولا يحتوي على ملفات باسم `TaskForm` أو `routes/tasks.js`. لذلك لم تتم إضافة ملفات غير مرتبطة ببنية المشروع فقط من أجل مطابقة أسماء موجودة في نشاط أو مثال مختلف. بدلًا من ذلك، تم تطبيق مفهوم التحقق ومعالجة الأخطاء على النماذج والمسارات الموجودة فعليًا في تطبيق KahrabaPay.

## ملاحظات مهمة

- بيانات المستخدمين والحسابات مخزَّنة في PostgreSQL.
- لا توجد كلمة مرور PostgreSQL مكتوبة مباشرة داخل `server.js`.
- أسرار قاعدة البيانات ومفتاح JWT تتم قراءتها من `.env`.
- كلمات المرور يتم التعامل معها باستخدام `bcryptjs`.
- الوصول إلى البيانات محمي بالمصادقة وملكية الحساب.
- التطبيق يحتوي على معالجة للأخطاء ومسار 404.
- بيانات الاستهلاك الموجودة في المشروع مخصصة للنموذج التجريبي والاختبار.
- التطبيق الحالي نموذج تجريبي لخدمات شركة الكهرباء، وليس نظامًا متصلًا مباشرة بأنظمة الشركة العامة للكهرباء. الربط الفعلي مع أنظمة الشركة العامة للكهرباء يحتاج إلى API رسمي أو تكامل معتمد.
